# 验证记录

日期：2026-10-22；v0.2.1 / v0.2.2 验证补充于 2026-10-23（America/Los_Angeles）

## 已完成的真机验证

- 讯飞助手 4.4.36.4；S1 通过蓝牙连接并成功握手。
- 实体按键 0 的按下/松开与开始/停止录音均收到设备回包。
- 编码 2、通道 0 的音频解码为 16 kHz 单声道、16-bit PCM；多轮本地录音成功。
- 使用者回放后确认声音清楚，并确认输入法联动链路跑通。
- 独立 S1 Bridge Audio 驱动安装回执和签名均有效；重启系统音频服务后，CoreAudio 枚举到双向虚拟设备，豆包设置界面识别到该输入。
- Fn、按住型触发、S1 Bridge Audio 输出配置已在原版实际使用。

## v0.2.0 离线验证

- 老版本设置文件缺少自动连接字段时仍可读取，保留 Fn、音频设备与联动模式。
- 首次使用不连接未知设备；只恢复最后一次成功设备。
- 连接请求去重；失败退避；主动断开后暂停；蓝牙关闭与电脑休眠期间不发起连接；恢复后允许重连。
- 验证拒绝后暂停，手动成功选择新设备后更新目标。
- 重复按键、非当前按钮松开、紧急停止、尾音结束、错误清理与通道过滤。
- 真实的已安装讯飞协议解析器对完整/分片合成帧输出正确按键事件。
- 原生音频解码器初始化、WAV 文件结构、录音内容与原生 App/Python 进程通信。
- 便携 App 换目录后，在不含外部 Python 的 PATH 中自检通过，运行时前缀指向包内 Python。
- App 与音频驱动的本地签名通过检查；构建测试不接触麦克风、不模拟实际快捷键。

- 辅助功能按钮按真实权限状态显示，App 重新激活时刷新；请求权限前检查是否已经授权。
- 构建包含原生离线自检；本次仍保留 ad-hoc 签名，未声称解决签名变化造成的升级授权问题。
- 最终 ZIP 解压后的签名、原生自检、Python 路径迁移与包内容检查通过。
- 本机从 v0.2.1 更新到 v0.2.2 后，诊断确认一次自动重连及设备握手成功；这不代替多轮设备开关和休眠验收。此次升级后的辅助功能状态为未授权，未自动修改系统授权记录。

## v0.3.0 预览版（2026-10-27）

- 内置有线耳机 HID 按下和松开事件已实测；独占接管后使用者确认 Siri 不再弹出，释放接管成功，输入/输出设备未改变。
- 使用外置麦克风进行不保存音频的音量检查：长按期间的采样 RMS 为零，松开后恢复，因此默认采用点按开关。
- 新增的手势状态、重复边沿、取消、模式退出、休眠清理和设备匹配边界有离线检查。
- 完整 App（构建 5、6）的输入监控和辅助功能授权已由使用者完成；使用者通过有线耳机发送消息，并确认构建 6 的点按开始、点按结束均正常。
- 运行诊断记录了多轮开始/结束，以及一次达到 120 秒上限后的自动结束；正常退出后确认耳机接管已释放。
- 离线场景复现了菜单跟踪模式下普通计时器暂停的问题；耳机事件和安全计时改为公共运行模式，并加入回归检查。Fn 组合键保留修饰键的检查也通过。
- 发布包构建 7 在上述构建 6 基础上增加了切换模式取消未完成快捷键录入的清理；安装包、签名、解压运行、核心/协议自检通过。构建 7 未另做完整硬件输入验收；本机保留已授权的构建 6。
